# Known limitations (true statements; none is a blocker for the release graph)

| # | Component | Limitation | Why it is acceptable now / follow-up |
|---|---|---|---|
| 1 | actenon-kernel wheel | Installs top-level packages `conformance`, `examples`, `schemas` into site-packages (identical in published 1.2.1). A project with its own top-level module of those names can collide. | Pre-existing layout; the runtime locates vectors through them. Follow-up: move them under `actenon/` in a minor release with a compatibility shim. |
| 2 | actenon-protocol | The hash-locked conformance vectors are not in the wheel or the sdist. They are distributed through the release tag (`conformance/vectors/`, `vectors.sha256`). `runner.py` copied out of a checkout uses the installed package's schemas (fixed in 1.4.0). | The fresh-consumer test takes them from the tag archive and verifies `vectors.sha256`. Follow-up: ship them as package data or attach them to the GitHub release. |
| 3 | actenon-kernel CI | No ruff or lint gate over `actenon/`; 19 pre-existing findings (unused imports, E402 ordering, an F821 string annotation, unused locals in a shipped conformance test). The F601 duplicate key was removed. | None changes behaviour (verified individually). Follow-up: add a lint job and fix them in one change. |
| 4 | actenon-protocol CI | Lint scope is `python/` and `conformance/python/`; `conformance/runner.py` and `scripts/` carry pre-existing findings (F401/F841/F541/E402/B905). | Behaviour is covered by tests that drive `runner.py` over every vector. Follow-up: widen the scope. |
| 5 | actenon-permit wheel | Ships `actenon_permit/_iam_stub.py`, a test IAM stub server with a fixed, documented-as-non-production secret. No production module imports it. | Private module, opt-in only. Follow-up: move it to tests. |
| 6 | actenon-permit | `[tool.hatch.metadata] allow-direct-references = true` remains after release preparation. | The 2.0.0 wheel has no direct references (ARTEFACT-METADATA-CHECK). Follow-up: remove the setting. |
| 7 | Build reproducibility | Wheels, npm tarballs, the crate and the Go module zip are byte-reproducible from a commit. sdists and the Go proxy `.info` file carry build timestamps. | Release verification compares content (`rehearsal/compare_artefact_contents.py`) or content hashes (Go `h1:`). |
| 8 | Timestamp grammar | RFC 3339 is enforced. Two ecosystem conventions are kept: the space separator (accepted by the reference and Rust, refused by TS and Go: fail-closed B) and lower-case `t` (same split). Lower-case `z` is refused everywhere. | Measured by the frozen timestamp-grammar addendum. Covered by the differential addendum and per-SDK unit tests, not yet by shipped conformance vectors. Follow-up: add vectors in a later conformance version. |
| 9 | Go SDK | Edge parameter constraints decoded as `float64` are refused (`PARAMETER_MISMATCH`); edges must decode their declarations with `json.Decoder.UseNumber`. | Documented on `VerificationContext`. This is the Go-strict B in CROSS-LANGUAGE-PARITY.md. |
| 10 | TS SDK | Integers at or beyond 2^53 are refused; no replay enforcement in the TS SDK (verification only). | Documented in its README. |
| 11 | Kernel | Reconciliation and Policy Bundle are reserved, inactive surfaces (2 documented skips). | README states they are not v1 conformance targets. |
| 12 | Branch protection | Could not be read or set from this session. | OWNER-ACTIONS A3. |
| 13 | actenon-blastradius | Published 0.4.0 has known destructive-command bypasses; the fixes are unmerged and unreleased. | BLASTRADIUS.md; OWNER-ACTIONS A10/B3. |
